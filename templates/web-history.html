Introduction: the History of the Web

The World Wide Web is a system of documents that are linked together and can be accessed through the internet. Both the web and the internet are interconnected, but they are not the same thing. The internet is the network that carries the data of the Web. The Web began between 1989 and 1991, when Tim Berners-Lee proposed a way for scientists to link their documents together on various computers without the need to exchange them manually, and it has grown and changed completely ever since.

1. Birth of the Web at CERN

Event: Tim Berners-Lee, a researcher at CERN, wrote "Information Management: A Proposal" in March 1989, describing an internet-based hypertext system for linking documents on different computers. With Robert Cailliau he refined it into a formal proposal in November 1990 and, by the end of that year, had built the three building blocks of the Web — HTML for formatting documents, HTTP for transferring them, and URLs for identifying them — together with the first browser/editor and web server, which ran on a NeXT computer. The first website went live at info.cern.ch on August 6, 1991.

Why it mattered: The Web is the application layer that made the internet browsable and usable by non-specialists, turning a network for technical users into a system of interlinked, navigable documents that could be published by anyone.

Sources:

  • CERN, "The birth of the Web," CERN.
  • World Wide Web Consortium, "History," W3C.
  • T. Berners-Lee, "The World Wide Web project" (1992 copy of the first project pages), W3C.

2. A Free, Open Web: the Public-Domain Release and Mosaic

Event: On April 30, 1993, CERN put the World Wide Web software in the public domain, so that anyone could run a server or write a browser without paying royalties or asking permission. That same year, Marc Andreessen and Eric Bina at the University of Illinois's National Center for Supercomputing Applications (NCSA) released Mosaic, a browser for Windows, Macintosh and Unix that displayed images inline with the text and was distributed free of charge.

Why it mattered: CERN's royalty-free release is credited with the Web's rapid, unrestricted adoption, and Mosaic's ease of use is widely credited with turning the Web from an academic tool into something ordinary people could use — it set the visual and navigational template for every browser that followed.

Sources:

  • CERN, "Twenty years of a free, open web," CERN News, Apr. 30, 2013.
  • Internet Hall of Fame, "Marc Andreessen," Internet Society.
  • Internet Hall of Fame, "Eric Bina," Internet Society.

3. The W3C and the Standardization of the Web

Event: In October 1994 Tim Berners-Lee founded the World Wide Web Consortium (W3C) at MIT, in collaboration with CERN, DARPA and the European Commission, to steer the Web's development so that no single company could control it. The W3C then published specifications that any browser could implement: HTML 2.0 in 1995, CSS1 for styling in December 1996, and HTML 4 in 1997.

Why it mattered: Shared, royalty-free standards are what let pages written once display correctly in every browser and prevented the Web from splitting into incompatible versions owned by competing vendors. That is still how the Web is developed today.

Sources:

  • World Wide Web Consortium, "History," W3C.
  • T. Berners-Lee and D. Connolly, "Hypertext Markup Language — 2.0" (HTML 2.0 specification), W3C, 1995.
  • H. W. Lie and B. Bos, "Cascading Style Sheets, level 1" (CSS1), W3C Recommendation, Dec. 1996.

4. The Dynamic, Scriptable Web

Event: JavaScript, written at Netscape in 1995 by Brendan Eich, was standardized as ECMAScript in ECMA-262 in 1997, and XML 1.0 became a W3C Recommendation in February 1998. HTTP/1.1 was published as RFC 2616 in June 1999. Together with the XMLHttpRequest object, these technologies let a page request new data and update part of itself without reloading — the technique later called Ajax.

Why it mattered: Pages stopped being static documents and became applications that run inside the browser. This is the foundation of every modern web application, from maps and mail clients to the sites and frameworks used today.

Sources:

  • Ecma International, "ECMA-262: ECMAScript language specification," Ecma International.
  • T. Bray, J. Paoli, C. M. Sperberg-McQueen, E. Maler, and F. Yergeau, "Extensible Markup Language (XML) 1.0," W3C Recommendation, Feb. 1998.
  • R. Fielding, J. Gettys, J. Mogul, H. Frystyk, L. Masinter, P. Leach, and T. Berners-Lee, "Hypertext Transfer Protocol — HTTP/1.1," RFC 2616, Internet Engineering Task Force, Jun. 1999.

5. The Mobile Web and HTML5

Event: As smartphones and tablets spread through the 2000s and 2010s, browsing moved from desktop computers to small touch screens, and sites switched to responsive layouts that adapt to any screen size. In parallel, the W3C worked on a new version of the language: HTML5 became a W3C Recommendation on October 28, 2014, adding native audio and video playback without plugins, the canvas element for drawing and animation, native support for SVG and MathML, and better accessibility features.

Why it mattered: HTML5 brought to the browser what previously required separate plug-ins, and the mobile Web made the Web the first place most people now go online. Together they turned the Web from a collection of pages into the platform that applications are delivered on.

Sources:

  • World Wide Web Consortium, "Open Web Platform Milestone Achieved with HTML5 Recommendation," W3C Press Release, Oct. 28, 2014.
  • I. Hickson, R. Berjon, S. Faulkner, T. Leithead, E. D. Navara, E. O'Connor, and S. Pfeiffer, "HTML5: A vocabulary and associated APIs for HTML and XHTML," W3C Recommendation, Oct. 28, 2014.
  • World Wide Web Consortium, "History," W3C.

6. Today's Web

Event: The way pages travel is being rebuilt for today's traffic: HTTP/2 (RFC 7540, May 2015) and HTTP/3 (RFC 9114, June 2022) replaced much of HTTP/1.1's behaviour and moved delivery onto faster, encrypted transports. In December 2019, WebAssembly became a W3C Recommendation, allowing code compiled from other languages to run in the browser at near-native speed.

Why it mattered: These changes made the Web fast and capable enough to host software that used to require an installed application, and the standards process behind them keeps the Web open to any browser and any user rather than tied to one vendor.

Sources:

  • M. Belshe, R. Peon, and M. Thomson, "Hypertext Transfer Protocol Version 2 (HTTP/2)," RFC 7540, Internet Engineering Task Force, May 2015.
  • M. Bishop, "HTTP/3," RFC 9114, Internet Engineering Task Force, Jun. 2022.
  • A. Rossberg, "WebAssembly Core Specification," W3C Recommendation, Dec. 5, 2019.
